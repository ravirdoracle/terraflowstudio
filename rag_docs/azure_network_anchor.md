# Oracle Network Anchor and Resource Anchor on Azure (Oracle AI Database@Azure)

## What a Network Anchor is
A Network Anchor is the network bridge between an Azure subscription and OCI for
Oracle AI Database@Azure. It is **not tied to one database service** — it is a
networking resource in its own right. It takes **its own delegated subnet**
(delegated to `Oracle.Database/networkAttachments`), and OCI builds a VCN and a
subnet behind it in the compartment of the Resource Anchor it references. The OCI VCN
carries the Network Anchor's name.

Oracle's documentation states that creating a Network Anchor requires an existing
Resource Anchor and a delegated subnet, and that it is a prerequisite for creating
Oracle AI Database@Azure resources.

## What a Resource Anchor is
A Resource Anchor (`azurerm_oracle_resource_anchor`) maps an Azure resource group to
an OCI compartment. Its `location` and `linked_compartment_id` are assigned by the
service. A Network Anchor needs one — either a Resource Anchor card in the same
Terraflow configuration, or an existing one given by its Azure resource ID
(`/subscriptions/.../providers/Oracle.Database/resourceAnchors/<name>`).

## How Terraflow generates a Network Anchor (azapi)
azurerm has **no Network Anchor resource** (checked up to azurerm 5.12.0). Terraflow
generates it with the `azure/azapi` provider:
`azapi_resource` with `type = "Oracle.Database/networkAnchors@2025-09-01"`, the GA API
version. API version 2026-06-01 has the same properties plus a proximity placement
group, which Terraflow does not surface.

- Provider floor: **azure/azapi >= 2.8.0**. Found by pinning each release and running
  `terraform validate`: 2.5.0–2.7.0 reject the resource type, 2.4.0 has no
  `ignore_null_property`.
- `terraform validate` checks the request body against Azure's published schema
  offline, so a misspelt property fails validation, not apply.
- `ignore_null_property = true` keeps unset optional settings out of the request.
- azapi is added to `required_providers`, with a `provider "azapi"` block, only when
  a configuration has a Network Anchor. Configurations without one are unchanged.
- Oracle's documentation describes creation through the Azure Portal only; the
  generated Terraform calls the same Azure Resource Manager API the portal uses.

## Network Anchor fields
| Field | API property | Notes |
|---|---|---|
| name | resource name | 3–24 letters, digits or hyphens |
| Resource Anchor | `resourceAnchorId` | required |
| subnet | `subnetId` | required; the anchor's own delegated subnet, created by the module |
| zone | `zones` | availability zone 1, 2 or 3; optional |
| oci_vcn_dns_label | `ociVcnDnsLabel` | optional when DNS is configured |
| oci_backup_cidr_block | `ociBackupCidrBlock` | OCI backup subnet CIDR; optional |
| DNS zone replication | `isOracleToAzureDnsZoneSyncEnabled` | copy the databases' private zones from OCI to Azure |
| DNS listening endpoint | `isOracleDnsListeningEndpointEnabled` | Azure resolves database FQDNs through OCI |
| allowed CIDRs | `dnsListeningEndpointAllowedCidrs` | comma-separated in the API; needs the listening endpoint |
| DNS forwarding endpoint | `isOracleDnsForwardingEndpointEnabled` | databases resolve Azure private FQDNs |
| forwarding rules | `dnsForwardingRules` | domain names + the IP of an Azure DNS inbound endpoint; need the forwarding endpoint |

Read-only results exported as outputs: `ociVcnId`, `ociSubnetId`, `cidrBlock`,
`dnsListeningEndpointIpAddress`, `dnsForwardingEndpointIpAddress`.

## Network Anchor gotchas
- **Its subnet is its own.** Do not reuse the VNet's VM-cluster delegated subnet. The
  validator rejects a Network Anchor subnet that overlaps the VNet's delegated subnet,
  falls outside the VNet address space, or overlaps another Network Anchor's subnet.
- **DNS zone replication and the DNS listening endpoint overlap.** Oracle's portal
  describes them as overlapping functions and asks for one or the other; the
  validator rejects both together.
- **Only the backup CIDR and the three DNS flags are updatable** in the API's update
  model. The Resource Anchor, subnet, zone and VCN DNS label are the anchor's
  identity; changing them in tfvars fails at apply rather than replacing the anchor.
- **Proximity placement group** cannot be added after creation (Oracle docs) and is
  not generated by Terraflow.
- **Deploy order:** Resource Anchor → VNet → Network Anchor (its subnet is created
  first, inside the same module). `terraform apply -target=module.<name>`.
