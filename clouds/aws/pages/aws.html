Manage the integration in this configuration
Needed by any database that reads its ADMIN password from Secrets Manager. It is one per AWS account and Region, shared by every Autonomous Database there. Turning this on adopts an integration that is already enabled; the module sets prevent_destroy, because destroying it disables Secrets Manager passwords for databases outside this configuration too. Leave it off if another configuration or team already manages it.

aws_kms_tde_key
guide ↗
ℹ Keep the TDE master key of this configuration's VM clusters in a customer-managed AWS KMS key instead of the local wallet. Each key is created (or adopted by ARN); every cluster it serves gets an IAM role it assumes through the OCI identity domain, plus a KmsTde association; and the key is registered in OCI — all in one apply, with the aws and oracle/oci providers. The clusters' ODB Network needs sts_access and kms_access = ENABLED.
⚠ One manual step after apply — no provider exposes it: OCI console → Exadata VM Clusters → the cluster → VM Cluster information → AWS Key Management → Enable. Then a CDB can use the key: terraform output aws_kms_keys gives its oci_key_id.
